# Установка и восстановление Keenetic Start KN-1112

Инструкция предназначена только для **KN-1112**. Основание — [инструкция в коммите поддержки этой модели в OpenWrt](https://github.com/openwrt/openwrt/commit/ca866328d555692e91e870bdeb368a830b39ceba). Для другой модели или аппаратной ревизии нужен её собственный образ и способ восстановления.

**Вход в режим восстановления запускает загрузку файла и последующую запись прошивки загрузчиком.** Включайте этот режим только после проверки готового образа, контрольной суммы и модели. TFTP-сервер ниже сам не меняет настройки компьютера или роутера и не отправляет команду прошивки, но успешная передача файла загрузчику приводит к перепрошивке. Самостоятельно останавливать питание во время записи нельзя.

## Перед началом

- Сохраните резервную копию действующих настроек роутера и проверенный способ возврата к штатной KeeneticOS. Для возврата используйте официальный образ и утилиту восстановления именно KN-1112.
- Запишите текущие IPv4-настройки проводного адаптера компьютера: автоматическое или ручное получение адреса, адрес, маску, шлюз и DNS. После процедуры восстановите их.
- Для первой установки используйте проверенный образ **`*-squashfs-factory.bin`**. Файл `*-sysupgrade.bin` предназначен для последующих обновлений уже установленного OpenWrt, а не для первой загрузки через штатный загрузчик.
- Подключите компьютер Ethernet-кабелем к одному из портов **1–3** роутера. Отключите от роутера кабель внешнего Интернета. Для восстановления используйте проводное соединение.
- Настройте на проводном адаптере компьютера адрес **192.168.1.2**, маску **255.255.255.252** (`/30`). Сервер должен быть привязан именно к этому адаптеру. Другие адаптеры и маршруты не изменяйте.

Точный адрес самого роутера в режиме восстановления в указанном коммите не приведён. Для описанного способа компьютер выступает TFTP-сервером, а загрузчик роутера сам запрашивает файл; отправлять файл командой TFTP-клиента на предполагаемый адрес роутера не нужно.

## Запуск сервера на компьютере

Нужен Python 3. Дополнительные пакеты не требуются. Из корня проекта запустите, подставив путь к проверенному factory-образу:

```powershell
python scripts/serve-recovery.py --bind 192.168.1.2 --image "D:\path\verified-squashfs-factory.bin"
```

По умолчанию используется UDP-порт **69**. При необходимости разрешите этому процессу входящие UDP-пакеты на выбранном проводном интерфейсе средствами межсетевого экрана. Для передачи используется также выделенный сервером временный UDP-порт. Скрипт не изменяет правила межсетевого экрана и настройки сети. Если порт занят, остановите другую службу TFTP; смена порта через `--port` предназначена для проверки, загрузчик ожидает стандартный порт.

Сервер выдаёт выбранный файл только под именем **`KN-1112_recovery.bin`**. Переименовывать исходный файл на диске не требуется. Другие имена, запросы записи и пути к каталогам отвергаются. Во время работы показываются количество переданных и подтверждённых байтов и результат передачи. Это подтверждает передачу файла, но не завершение записи или успешную загрузку прошивки.

## Действия на роутере

1. Убедитесь, что образ проверен, сервер ожидает запрос и Ethernet-кабель подключён к порту 1–3.
2. При отключённом питании зажмите заднюю кнопку **Reset**.
3. Продолжая удерживать Reset, включите питание роутера.
4. Когда индикатор **Power** начнёт мигать, отпустите Reset.
5. Дождитесь передачи и завершения записи с последующей перезагрузкой. Не отключайте питание и кабель во время процедуры. Время зависит от устройства и соединения; скорость и длительность не гарантируются.

Альтернативный способ из того же коммита: скачать официальную утилиту восстановления KN-1112, заменить в её каталоге `fw` файл **`KN-1112_recovery.bin`** проверенным factory-образом и следовать указаниям утилиты. Не запускайте два TFTP-сервера одновременно.

## После загрузки proxys22

1. Остановите TFTP-сервер сочетанием **Ctrl+C**.
2. Если компьютер получает основной интернет через другой интерфейс, для настройки задайте на Ethernet **192.168.2.2/24**, оставив **шлюз и DNS пустыми**. Так неготовый туннель не перехватит основной маршрут компьютера. Автоматическое получение адреса используйте, когда намерены направить и сам компьютер через уже настроенный Keenetic. Остальные адаптеры не изменяйте.
3. Адрес локального интерфейса новой системы — **192.168.2.1**. Wi-Fi изначально выключен; первую настройку выполняйте по Ethernet.
4. Предустановленного пароля root нет. Владелец должен сначала подключиться по проводному SSH и выполнить **`passwd`**, установив собственный пароль, и только после этого включать Wi-Fi и настраивать профиль Hysteria. Не открывайте доступ управления со стороны внешней сети.
5. Проверьте проводной и Wi-Fi-источник Интернета, работу TCP/UDP и DNS через туннель, переход на обычный IPv4-интернет при остановке туннеля и возврат к прокси после восстановления.

## Обновление установленной ОС

Для KN-1112 с уже установленной нашей ОС используйте только `*-sysupgrade.bin`.
Перед обновлением сохраните `sysupgrade -b`, профиль и резервный образ; проверьте
контрольную сумму и `sysupgrade -T` на самом устройстве. Обновление выполняется
с сохранением настроек, без `-n` и без принудительного `-F`.
При переходе с 0.1.0 сохраните `/etc/wifi-proxy/initialized` через
`/etc/sysupgrade.conf`: это предотвращает сброс Wi-Fi и LAN стартовым скриптом.
Не переносите старые `/www` или init-скрипты поверх новой системы.
Переключение между прямым подключением и прокси меняет внешний адрес;
существующие соединения могут потребовать переподключения.

Программные тесты TFTP-сервера выполняются на localhost и высоких временных портах. Фактическая установка, загрузка образа, работа радио, туннеля и защиты от прямого выхода требуют проверки на физическом KN-1112. Контрольная сумма и успешная передача не заменяют такую проверку.
