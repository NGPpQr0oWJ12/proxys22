# proxys22

Собственная компактная прошивка на базе OpenWrt для **Keenetic Start KN-1112**.
KeeneticOS полностью заменяется. Собственный интерфейс без LuCI и внешних зависимостей;
AmneziaWG в ядре и отдельный Hysteria 2 без универсального прокси-комбайна.

## Состав

- OpenWrt 25.12.2, `ramips/mt76x8`, профиль `keenetic_kn-1112`.
- Hysteria 2.13.0, MIPS little-endian soft-float, официальный бинарник с проверкой SHA-256.
- Модуль AmneziaWG собран под ядро 6.12.74 из соответствующего OpenWrt SDK; пины в `config/amneziawg.json`.
- Прозрачный IPv4 через AmneziaWG (policy routing/NAT) или Hysteria (TPROXY); DNS через активный туннель.
- При недоступности активного туннеля IPv4 автоматически переходит на обычное подключение;
  после двух успешных проверок возвращается к прокси. DNS переключается вместе с маршрутом.
- Ethernet DHCP или Wi-Fi WPA/WPA2 в качестве источника интернета; отдельная Wi-Fi сеть клиентов WPA2.
- Вход администратора через штатные rpcd/ubus; токен сессии хранится в `sessionStorage` текущей вкладки и сохраняется при обновлении страницы. Пароль не сохраняется.
- Импорт `hy2://` / `hysteria2://`, включая Salamander. Пароли не возвращаются API статуса.
- Импорт текста `.conf` AmneziaWG с одним IPv4-адресом /32 и одним peer. Команды wg-quick запрещены.
- Белая панель: CPU, график трафика, поиск Wi-Fi и список устройств с блокировкой доступа в интернет.
- Проверка TLS включена. Для самоподписанного сертификата нужен `pinSHA256`.

Серверные данные 3x-ui в образ не включаются. Профиль клиента хранится на роутере
в `/etc/wifi-proxy/client.json` и `/etc/wifi-proxy/awg.json` с правами 0600, сохраняется при sysupgrade.
Импорт выбирает протокол; другой профиль сохраняется. Данные администратора 3x-ui роутеру не нужны.
Bootstrap DNS самого роутера использует внешние DNS до установления туннеля;
DNS клиентских устройств обслуживается через активный туннель и напрямую в резервном режиме.

## Терминальная утилита Windows / Linux

Интерактивное меню и команды первичной прошивки, обновления, загрузки образов,
резервного копирования и диагностики: [docs/terminal.md](docs/terminal.md).
Готовые программы и актуальные factory/sysupgrade-образы публикуются вместе
в [GitHub Releases](https://github.com/NGPpQr0oWJ12/proxys22/releases/latest).
Утилита получает последний стабильный релиз и проверяет SHA-256; перед обновлением
сохраняет проверенную резервную копию и выполняет `sysupgrade -T`.

```text
python -m pip install -r requirements-manager.txt
python proxys22.py
```

## Сборка прошивки

Пины и контрольные суммы: [config/build.json](config/build.json).
Нужна Linux x86-64 среда с зависимостями OpenWrt ImageBuilder; сборка производится
на ext4 в `/opt/wifi-proxy`. На этом компьютере подготовлен отдельный WSL-дистрибутив
`WifiProxyBuild`.

```powershell
.\scripts\bootstrap-build.ps1
```

Скрипт берёт только `overlay/`, проверяет входные бинарники, собирает factory/sysupgrade,
проверяет ограничение **16 121 856 байт** и сохраняет результат, манифест и SHA-256 в `dist/`.
Каталог `.private/` исключён из Git и никогда не попадает в прошивку.

## Проверка

```text
node --check overlay/www/assets/app.js
python -m unittest discover -s tests -p test_*.py
ucode tests/profile.test.uc
ucode tests/awg.test.uc
```

`ucode` должен соответствовать версии OpenWrt. Для этой сборки проверяется commit
`85922056ef7abeace3cca3ab28bc1ac2d88e31b1`. Дополнительно проверены запуск RPC-плагина
под QEMU MIPS и синтаксис оболочки. Эмуляция не подтверждает работу Wi-Fi, TPROXY,
туннеля на реальном устройстве или скорость: эти проверки выполняются после установки.

Предпросмотр панели: запустить статический сервер из `overlay/www/`, открыть `/?demo=1`.
В деморежиме запросы к роутеру отключены; показанные значения являются примерами.

## Установка

Процедура первой установки и восстановления: [docs/recovery.md](docs/recovery.md).
Текущая версия — **proxys22 0.4.0**. Factory предназначен для первой установки через загрузчик, sysupgrade — для последующих
обновлений уже работающей нашей ОС. Обычная загрузка factory через веб-интерфейс Keenetic
не является проверенным способом установки.

Первый запуск: только проводная LAN, адрес роутера `192.168.2.1`, Wi-Fi выключен.
Владелец сначала задаёт пароль root командой `passwd` в проводном SSH-сеансе,
затем входит в панель, импортирует профиль, настраивает сеть клиентов и включает туннель.

## Ограничения первой версии

Только KN-1112; имя сервера/IPv4, один порт Hysteria без hopping/Realm/ECH.
Внешний Ethernet — DHCP; Wi-Fi источник — WPA/WPA2 PSK или открытая сеть. Клиентский IPv6 и остальные IP-протоколы
не пересылаются, чтобы исключить обход туннеля. Импорт по URL подписки пока отсутствует:
используется индивидуальная ссылка подключения из 3x-ui.
Для AmneziaWG используется текст `.conf`, `AllowedIPs = 0.0.0.0/0`, MTU 1280–1420.
Поддерживаются Jc/Jmin/Jmax, S1–S4, H1–H4; дополнительные заголовки/пакетные шаблоны
и ссылки `vpn://` пока не импортируются. Профиль должен соответствовать серверу.

CPU 575 МГц и 128 МБ RAM требуют измерений на устройстве. Скорость Hysteria заранее
не гарантируется. Размер QUIC-окон и целевой Go heap ограничены для этого оборудования.
Chrome Parrot отключён: в этой версии клиента он принудительно увеличивает окна до
6/15 МиБ, обходя заданные пределы памяти. Маскировка Salamander работает независимо.

Для настройки с компьютера, который получает основной интернет по другой сети,
используйте на Ethernet адрес `192.168.2.2/24` **без шлюза и DNS**. DHCP этого роутера
назначает его основным шлюзом; переходите на него, когда хотите направить компьютер
через настроенный туннель.
